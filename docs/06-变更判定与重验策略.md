# 06 变更判定与重验策略

## 1. 判定原则

“没有变化”不是只看页面截图。只有验收规格、被引用代码、API 契约、样式、数据、权限、浏览器和验收组件版本都满足复用条件，才可以不重复执行。

每次运行都记录两类 hash：

- `contentHash`：文件或输入内容的 hash；
- `semanticHash`：去掉无关格式、注释和时间字段后，对规范化内容计算的 hash。

默认使用 `semanticHash` 做场景判断，同时保留 `contentHash` 便于审计。任何无法证明等价的变化都按变化处理。

## 2. 场景指纹

```text
scenarioHash = hash(
  specHash,
  场景规范化 JSON,
  页面和路由 contentHash,
  直接及间接组件 semanticHash,
  API client 和 schema hash,
  路由、权限和登录态配置 hash,
  全局样式/token hash,
  测试数据快照 hash,
  浏览器和执行器版本
)
```

只有以下条件全部满足，才允许复用上次 `pass`：

- `scenarioHash` 相同；
- 运行环境和浏览器版本相同；
- 测试数据、权限和登录态配置相同；
- 原证据文件完整、可读取且未过期；
- 原结果没有 `needs_review`、`blocked` 或未解决的 finding。

复用只代表复用已验证证据，不能生成新的截图或请求记录。结果必须标记 `status: reused`，并引用原 `runId`。

## 3. 依赖影响范围

执行器维护反向依赖图：

```text
场景 → 页面 → 组件 → 公共组件/样式 → API client → schema → API 服务
```

- 页面业务文件变化：重跑该页面的场景；
- 局部组件变化：重跑直接或间接引用它的场景；
- API client 或 schema 变化：重跑触发该 API 的场景；
- API 路由、响应模型、权限或登录流程变化：重跑对应 API 的全部场景；
- 测试数据快照变化：重跑依赖该快照的场景；
- 浏览器、执行器、规则版本或模型版本变化：按版本策略全部重跑或至少重跑受影响场景；
- 仅与场景无关的文档变化：允许复用，但记录原因。

依赖无法解析时扩大重验范围，不能按“看起来没影响”复用。

## 4. 全局组件判定

全局组件必须在输入规格中登记影响级别和依赖边界：

```yaml
components:
  - id: AppButton
    path: src/components/AppButton.tsx
    exports: [AppButton]
    impact: interaction-and-visual
  - id: ThemeTokens
    path: src/styles/tokens.css
    exports: [color, spacing, typography]
    impact: visual-global
```

影响级别：

- `local`：只影响直接引用页面；
- `interaction`：重跑引用它的按钮、输入和提交场景；
- `data-display`：重跑引用它的列表、详情和分页场景；
- `visual`：重跑引用它的截图场景；
- `interaction-and-visual`：重跑所有引用页面的交互和视觉场景；
- `visual-global`：重跑全部视觉场景，关键交互场景至少抽样重跑；
- `runtime-global`：重跑全部场景。

无法获得可靠引用关系、组件导出范围或样式影响范围时，按 `runtime-global` 处理。

## 5. 选择结果

每次运行必须输出选择明细：

```json
{
  "selection": {
    "total": 48,
    "run": 12,
    "reused": 30,
    "skipped": 6,
    "items": [
      { "scenarioId": "edit-order", "action": "run", "reason": "AppButton changed" },
      { "scenarioId": "order-summary", "action": "reuse", "reusedFrom": "run-2026-10-17-abc" },
      { "scenarioId": "admin-export", "action": "skip", "reason": "not selected by current profile" }
    ]
  }
}
```

没有原因的 `skipped`、没有 `reusedFrom` 的 `reused` 或证据缺失，均视为执行器错误。

## 6. 强制失效

以下情况强制重新执行相关或全部场景：

- 验收规格主版本变化；
- 关键页面、公共组件、全局样式或 API 契约变化；
- 测试数据、权限模型或登录流程变化；
- 浏览器、Playwright、规则引擎或模型版本变化；
- 依赖图无法解析；
- 发现线上问题并新增回归场景；
- 原证据缺失、损坏、脱敏失败或超过保留期限。
