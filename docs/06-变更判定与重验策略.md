# 06 变更判定与重验策略

## 1. “没有变化”不能只看页面截图

页面不变但接口、权限、测试数据、公共组件或 CSS token 变化，仍可能改变验收结果。因此重验判定需要同时考虑代码、依赖、配置、数据和运行环境。

## 2. 场景指纹

为每个场景生成指纹：

```text
scenarioHash = hash(
  规范化后的场景 JSON,
  相关页面源码 hash,
  相关组件源码 hash,
  相关 API client 和 schema hash,
  路由和权限配置 hash,
  全局样式/token hash,
  package lock hash,
  测试数据版本,
  浏览器和执行器版本
)
```

只有以下条件全部相同，才允许复用上次结果：

- `scenarioHash` 相同；
- 相同代码提交或等价内容 hash；
- 相同浏览器和执行器版本；
- 相同测试数据快照；
- 相同权限和环境配置；
- 上次结果是 `pass`，且证据文件仍然可访问。

`failed`、`blocked` 和 `needs_review` 不得作为成功缓存复用。

## 3. 依赖图

执行器需要建立反向依赖图：

```text
场景 → 页面 → 组件 → 公共组件/样式 → API client → schema → API 服务
```

文件变化后沿反向依赖图找到受影响场景：

- 页面业务文件变化：重跑该页面场景；
- 局部业务组件变化：重跑引用该组件的场景；
- 公共 Button、Form、Modal、Drawer、Table 变化：重跑所有引用页面；
- 全局 CSS、主题 token、布局容器变化：重跑所有视觉场景，关键交互场景至少抽样重跑；
- API client 或 schema 变化：重跑所有触发该 API 的场景；
- API 路由、响应模型或权限配置变化：重跑对应 API 的所有前端场景和接口契约测试；
- package lock、浏览器版本或验收执行器变化：全部场景重跑；
- 仅文档、注释或与场景无关的服务端变化：可跳过无关场景，但要记录跳过理由。

## 4. 全局组件处理

全局组件不能按“文件是否直接出现在页面目录”判断。需要登记组件影响级别：

```yaml
components:
  - id: AppButton
    path: src/components/AppButton.vue
    impact: interaction-and-visual
  - id: AppTable
    path: src/components/AppTable.vue
    impact: data-display-and-visual
  - id: ThemeTokens
    path: src/styles/tokens.css
    impact: visual-global
```

影响级别建议：

- `local`：只影响直接引用页面；
- `interaction`：影响按钮、输入和交互场景；
- `visual`：影响布局和截图场景；
- `interaction-and-visual`：所有引用页面的交互和视觉场景；
- `visual-global`：全局视觉场景全部重跑。

无法解析依赖时，应扩大重验范围，而不是复用旧结果。

## 5. 变更结果

每次执行报告中记录：

```json
{
  "selection": {
    "total": 48,
    "run": 12,
    "reused": 30,
    "skipped": 6,
    "reason": "AppButton changed; affected pages selected"
  }
}
```

`reused` 必须附带上一次运行 ID 和指纹；`skipped` 必须附带原因。没有理由的跳过视为门禁错误。

## 6. 缓存失效原则

以下情况强制全部重验：

- 验收规格主版本变化；
- Playwright、浏览器或执行器版本变化；
- 公共组件依赖图无法解析；
- 测试数据快照变化；
- 权限模型或登录流程变化；
- 发现线上问题并新增回归场景；
- 上一次执行的证据缺失或损坏。
