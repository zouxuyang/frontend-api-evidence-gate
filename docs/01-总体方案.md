# 01 总体方案

## 1. 目标

把上游 Agent 描述的页面需求转换成可重复执行的验收任务，并输出后续 Agent 可以直接消费的证据化结果。组件验证页面能否操作、交互是否符合规格、数据是否进入正确 API、响应是否符合契约，以及关键布局和反馈是否可用。

## 2. 输入、处理、输出

### 输入

上游 Agent 提供结构化验收规格，至少包含：

- 页面和路由；
- 页面中的组件、按钮、输入、弹窗、抽屉及可访问名称；
- 用户交互步骤和预期状态；
- API 路径、方法、参数、请求体和响应 schema；
- 测试视口、数据场景、权限和质量要求；
- 页面、组件、API client、schema 和全局样式的依赖声明。

自然语言只用于补充业务目的和语义要求；可执行动作、元素定位、请求断言和通过标准必须结构化。

### 处理

1. 解析并规范化 YAML 或 JSON；
2. 校验必填字段、引用关系和动作类型；
3. 计算规格、代码、依赖、运行环境和数据快照指纹；
4. 根据指纹和依赖图选择 `run` 或 `reuse`；
5. 对需要执行的场景启动页面和 API，使用浏览器按步骤操作；
6. 采集截图、DOM、控制台、请求、响应和 trace；
7. 由规则引擎完成确定性断言，由模型完成声明范围内的语义复核；
8. 合并结论，生成结果 JSON 和证据索引。

### 输出

每个场景输出一个标准结果对象，至少包含执行状态、验收结论、指纹、复用信息、检查明细、请求明细、响应结果、截图路径和模型复核依据。整个运行再输出场景汇总，供后续 Agent 判断修复、继续开发或验收通过。

## 3. 验收对象

每个功能以用户场景为单位，例如：

```text
进入订单列表
→ 显示加载状态
→ 输入搜索条件
→ 点击搜索并发送正确请求
→ 验证列表响应和分页
→ 打开编辑抽屉
→ 修改字段并提交
→ 验证请求体、响应和成功提示
→ 模拟失败并验证输入保留
```

## 4. 证据要求

- 浏览器证据：最终截图，必要步骤截图和 Playwright trace；
- API 证据：每个声明 API 的请求 URL、方法、query、headers 摘要、body、状态码、响应 headers 摘要和响应 body；敏感值必须脱敏；
- 规则证据：断言的 expected、actual、状态和失败原因；
- 模型证据：模型结论、置信度、引用的截图或检查 ID；
- 过程证据：运行版本、执行时间、输入规格版本、是否复用以及阻塞原因。

缺少必要证据时只能是 `blocked` 或 `needs_review`，不能输出 `pass`。

## 5. 结论规则

- 确定性规则失败：`fail`；
- 页面、API、数据或模型服务不可用：`blocked`；
- 规则通过且模型复核通过：`pass`；
- 规则通过但模型低置信、证据缺失或发现语义问题：`needs_review`；
- 已验证且指纹和复用条件满足：`reused`，沿用原结论并保留原证据引用。
