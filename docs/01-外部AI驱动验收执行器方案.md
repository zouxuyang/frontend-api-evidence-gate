# 外部 AI 驱动验收执行器完善方案

## 1. 定位

本项目定位为一个被外部 AI 调用的确定性浏览器验收执行器。

```text
外部 AI
  → 生成结构化验收任务
  → 调用验收执行器
  ← 返回结论和证据
  → 根据失败证据决定修复或重新验收
```

验收执行器不负责自然语言理解、测试步骤规划、业务代码修改或业务语义决策。它只负责按照结构化任务执行浏览器操作，验证页面和接口，并保存可复核证据。

## 2. 目标和边界

### 目标

- 接受外部 AI 生成的 JSON 或 YAML 验收任务；
- 启动隔离浏览器，或连接用户已经打开并登录的浏览器标签页；
- 执行页面操作、表单校验和接口断言；
- 采集逐步截图、请求、响应、控制台、DOM 和 trace；
- 输出稳定的机器可读结果，供外部 AI 继续处理；
- 在证据不足、浏览器不可用或连接失败时明确返回 `blocked`，不猜测通过。

### 边界

本工具不嵌入自然语言模型，也不允许模型绕过输入协议直接控制浏览器。外部 AI 必须先生成并提交经过 Schema 校验的结构化任务。

## 3. 调用方式

核心能力通过同一套执行器实现，提供三种入口：

### TypeScript API

```ts
import { runAcceptance } from '@frontend-api-evidence-gate/runner';

const result = await runAcceptance({
  task,
  outputDir: './artifacts'
});
```

### CLI

```bash
acceptance-runner run acceptance-task.json --output ./artifacts
```

### 本地 HTTP 或 MCP 包装层

项目提供 `acceptance-runner-server`，支持 `POST /run`、异步任务查询/取消和最小 MCP JSON-RPC 的 `tools/list`、`tools/call`。包装层只负责参数校验、任务启动和结果返回，不能复制一套浏览器执行逻辑。

## 4. 输入协议

输入协议统一使用 `acceptance-task.schema.json`。任务至少包含任务标识、浏览器目标、页面、接口、场景和质量要求。

```json
{
  "taskId": "order-search-check",
  "taskVersion": 1,
  "browser": {
    "mode": "existing",
    "connection": {
      "type": "cdp",
      "endpoint": "http://127.0.0.1:9222"
    },
    "target": {
      "url": "http://localhost:4173/orders",
      "tabTitle": "订单列表"
    }
  },
  "pages": [{ "id": "order-list", "path": "/orders" }],
  "apis": [{
    "id": "list-orders",
    "method": "GET",
    "path": "/api/orders"
  }],
  "scenarios": [{
    "id": "search-order",
    "page": "order-list",
    "steps": [
      {
        "id": "fill-keyword",
        "action": "fill",
        "target": { "label": "搜索订单" },
        "value": "ORD-001"
      },
      {
        "id": "submit-search",
        "action": "click",
        "target": { "role": "button", "name": "搜索" }
      },
      {
        "id": "check-request",
        "action": "assertRequest",
        "api": "list-orders",
        "expected": {
          "method": "GET",
          "query": { "keyword": "ORD-001" }
        }
      }
    ]
  }],
  "quality": {
    "screenshot": "each-step",
    "trace": true,
    "consoleErrors": "fail",
    "redactSensitiveData": true
  }
}
```

任务中的定位器、动作、接口断言和通过标准必须结构化。自然语言只能作为说明字段，不能直接执行。

## 5. 浏览器目标

### 5.1 隔离浏览器

用于 CI 和无人值守任务。执行器自行启动 Chromium、Firefox 或 WebKit，并创建独立上下文。

```json
{
  "browser": {
    "mode": "launch",
    "browser": "chromium",
    "headless": true
  }
}
```

### 5.2 已有浏览器和登录态

用于复用用户已经打开的页面。第一期仅支持 Chromium 的 Chrome DevTools Protocol（CDP）连接，再根据 URL、标题或页面标识选择目标标签页；已有浏览器模式明确不支持 Firefox 和 WebKit。

```json
{
  "browser": {
    "mode": "existing",
    "connection": {
      "type": "cdp",
      "endpoint": "http://127.0.0.1:9222"
    },
    "target": {
      "url": "http://localhost:4173/orders"
    }
  }
}
```

登录 Cookie、Authorization 和其他会话信息由浏览器上下文提供，不进入 AI 输入。若找不到唯一目标标签页，执行器返回 `blocked`，并列出候选页面摘要。

### 5.3 浏览器扩展桥接

普通浏览器默认不允许任意 npm 进程读取已打开标签页。面向普通用户时增加扩展桥接：用户授权一个标签页，扩展将授权后的页面连接到本地执行器。扩展负责授权和连接，浏览器操作、请求监听和证据生成仍由执行器完成。

## 6. 动作和定位器

第一期动作：`open`、`attach`、`click`、`fill`、`select`、`upload`、`press`、`waitFor`、`screenshot`。

第一期定位器：`role + name`、`label`、`placeholder`、`text`、`testId` 和 `css`。`xpath` 和任意 JavaScript 默认关闭，只有任务显式启用时才允许使用。

## 7. 断言

### 页面断言

支持元素可见、隐藏、可用或禁用，文本、输入值、URL、页面标题、加载状态、空状态、成功提示、错误提示，以及溢出、遮挡和视口布局。

### 表单断言

```json
{
  "id": "check-phone-validation",
  "action": "assertValidation",
  "target": { "label": "手机号" },
  "expected": {
    "visible": true,
    "message": "请输入正确的手机号"
  }
}
```

覆盖必填、格式、长度、范围、字段间依赖、提交后错误、错误提示文本，以及错误时输入内容是否保留。

### API 断言

覆盖请求 URL、方法、Query、Header 摘要、Body、响应状态码、响应 Body、JSON Schema、耗时和重复请求。

## 8. 证据目录

每个场景独立保存证据：

```text
artifacts/<runId>/<scenarioId>/
├── scenario-result.json
├── screenshots/
│   ├── 001-before.png
│   ├── 002-after-fill.png
│   └── 003-after-submit.png
├── requests.json
├── responses.json
├── checks.json
├── console.json
├── trace.zip
└── dom/
    └── final.html
```

每个步骤都包含 `stepId`、动作、状态、期望、实际值和 `evidenceRefs`。证据引用必须能定位到具体截图、请求、响应或检查记录。

## 9. 输出协议

```json
{
  "runId": "run-20261017-001",
  "taskId": "order-search-check",
  "status": "failed",
  "decision": "fail",
  "summary": {
    "total": 1,
    "passed": 0,
    "failed": 1,
    "blocked": 0
  },
  "scenarios": [{
    "scenarioId": "search-order",
    "status": "failed",
    "decision": "fail",
    "failedStep": "check-request",
    "reason": "接口返回 500",
    "evidence": {
      "screenshots": ["screenshots/003-after-submit.png"],
      "requests": "requests.json",
      "responses": "responses.json",
      "checks": "checks.json",
      "trace": "trace.zip"
    }
  }]
}
```

状态与结论分开：`passed + pass` 表示全部通过；`failed + fail` 表示确定性断言失败；`blocked + needs_review` 表示无法连接浏览器、页面或接口；`completed + needs_review` 表示证据不完整或存在待人工判断项；`reused + pass` 表示复用仍有效的历史证据。

## 10. 对现有实现的改造

现有实现已经具备 TypeScript API、CLI、Playwright 执行、请求响应监听、截图、trace、结果 JSON 和场景指纹。需要进行以下调整：

1. 将输入从 `AcceptanceSpec` 扩展为包含浏览器目标的 `AcceptanceTask`；
2. 新增任务和结果 Schema；
3. 将浏览器启动抽象为 `LaunchBrowserAdapter`、`CdpBrowserAdapter` 和 `ExtensionBrowserAdapter`；
4. 增加标签页匹配、连接检查和连接失败诊断；
5. 增加每一步截图、控制台、DOM 和表单验证证据；
6. 扩展动作和断言白名单；
7. 将请求与响应按请求 ID 稳定关联，并支持响应 JSON Schema；
8. 将敏感 Header、Cookie、Token 和可配置字段统一脱敏；
9. 移除核心流程对 `ModelAdapter` 的依赖；
10. 保留模型复核为外部可选能力，不得覆盖确定性规则失败；
11. 让 CLI、TypeScript API、HTTP 和 MCP 入口共用同一个执行器；
12. 为运行中任务增加超时、取消、进度和退出码协议。

## 11. 安全边界

- 只允许访问任务声明的 Origin；
- 已有标签页必须由用户授权或通过明确的 CDP 地址提供；
- 默认脱敏 Cookie、Authorization、Token、Secret 和密码字段；
- 不把登录态写入任务文件或模型输入；
- 任意脚本执行默认关闭；
- 外部 AI 只能提交结构化任务，不能绕过 Schema；
- 证据目录按运行任务隔离；
- 连接、操作和证据生成全部记录审计日志。

## 12. 实施顺序

### 第一阶段：外部调用协议

- 固定任务和结果 Schema；
- 统一 CLI、库接口和输出目录；
- 移除核心流程对模型的强依赖。

### 第二阶段：证据完善

- 每步截图；
- 请求响应关联；
- 控制台和 DOM 证据；
- 基础无障碍和横向溢出检查；
- 表单验证和 JSON Schema 断言；
- 失败步骤定位。

### 第三阶段：已有标签页

- 实现 CDP 连接；
- 实现标签页匹配；
- 增加连接失败诊断和登录态复用；
- 设计浏览器扩展桥接协议。

### 第四阶段：Agent 接入

- 提供本地 HTTP 和 MCP 入口；
- 支持库接口和 CLI 的超时、取消、响应体大小限制；
- 增加服务鉴权、并发上限和异步任务取消。
- 支持外部 AI 根据失败证据发起二次验收。

最终职责划分为：

```text
外部 AI：决定验收什么，并处理验收结果
本工具：严格执行验收，并证明实际发生了什么
```
