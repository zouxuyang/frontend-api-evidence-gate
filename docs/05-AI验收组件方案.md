# 05 AI 验收组件方案

## 1. 组件定位

组件接收标准化验收规格，自动执行浏览器场景、采集客观证据，并调用模型补充业务语义判断。模型不能自由浏览后凭感觉评分；所有判断都必须绑定输入规格和采集证据。

```text
标准输入
→ 解析、校验、规范化
→ 依赖指纹和场景选择
→ 浏览器执行
→ 请求/响应/截图/规则证据
→ 模型复核
→ 标准输出
```

## 2. 标准输入

建议文件名为 `acceptance-spec.yaml`，提交到被验收项目或独立验收任务目录。规范化后保存为 `normalized-spec.json`。

```yaml
specId: order-list
specVersion: 3
project:
  baseUrl: https://test.example.com
  frontendRevision: git:abc123
  apiRevision: git:def456
  browser: chromium-128

pages:
  - id: order-list
    route: /orders
    purpose: 查看和筛选订单
    viewports: [1440x900, 390x844]
    components:
      - id: order-table
        kind: table
        locator: { role: table }
        mustShow: [orderNo, status, amount, createdAt]
      - id: edit-drawer
        kind: drawer
        locator: { role: dialog }
        trigger: { role: button, name: 编辑 }

apis:
  - id: list-orders
    method: GET
    path: /api/orders
    query: { page: integer, pageSize: integer, keyword: string? }
    responseSchema: OrderPage
  - id: update-order
    method: PATCH
    path: /api/orders/:id
    requestSchema: UpdateOrder
    responseSchema: Order

scenarios:
  - id: search-and-page
    page: order-list
    priority: critical
    steps:
      - open: /orders
      - fill: { label: 搜索订单, value: ORD-001 }
      - click: { role: button, name: 搜索 }
      - assertRequest:
          api: list-orders
          query: { page: 1, pageSize: 20, keyword: ORD-001 }
      - assertResponse: { api: list-orders, schema: OrderPage, status: 200 }
      - click: { role: button, name: 下一页 }
      - assertRequest: { api: list-orders, query: { page: 2, pageSize: 20, keyword: ORD-001 } }

  - id: edit-order
    page: order-list
    priority: critical
    steps:
      - open: /orders
      - click: { role: button, name: 编辑 }
      - assertVisible: { role: dialog }
      - fill: { label: 备注, value: 需要尽快处理 }
      - click: { role: button, name: 保存 }
      - assertRequest: { api: update-order, body: { remark: 需要尽快处理 } }
      - assertResponse: { api: update-order, schema: Order, status: 200 }
      - assertVisible: { text: 保存成功 }

quality:
  screenshot: required
  accessibility: critical
  forbiddenConsoleErrors: true
  maxRequestMs: 3000

data:
  snapshot: order-list-fixture-v3
  cases: [normal, empty, error, long-text]

components:
  - id: AppButton
    path: src/components/AppButton.tsx
    impact: interaction-and-visual
  - id: ThemeTokens
    path: src/styles/tokens.css
    impact: visual-global
```

输入必须区分页面、组件、动作、预期请求、响应 schema、测试数据和运行环境。`purpose` 等自然语言字段可以交给模型理解，但定位器、动作参数、API 断言和通过标准必须结构化。

## 3. 规范化处理

组件将 YAML 转为确定性的 JSON：

- 按键排序，数组按声明顺序保留；
- 补齐默认 viewport、超时和证据要求；
- 统一路由、API 路径、HTTP 方法和枚举大小写；
- 校验页面、组件、API、schema 和场景引用；
- 将动作限制为 `open`、`click`、`fill`、`select`、`upload`、`assertVisible`、`assertRequest`、`assertResponse` 等有限集合；
- 生成 `specHash`，相同语义输入必须得到相同 hash。

模型可以把自然语言初稿转换成规格，但转换后必须经过 schema 校验；未校验的模型输出不得执行。

## 4. 标准执行过程

1. 校验 `normalized-spec.json` 和运行环境；
2. 建立页面、组件、API、schema、样式、数据和场景的依赖图；
3. 计算场景指纹，选择 `run` 或 `reuse`；
4. 为 `run` 场景准备隔离浏览器上下文、登录态和数据快照；
5. 按步骤执行浏览器动作；
6. 监听导航、DOM、控制台、请求和响应；
7. 在最终状态和声明的关键步骤截图；
8. 保存请求明细、响应结果、trace、规则检查和脱敏日志；
9. 对请求、响应、布局和无障碍执行确定性检查；
10. 将规格、截图和规则证据提交模型复核；
11. 合并结论，输出结果 JSON 和证据目录。

推荐目录：

```text
artifacts/<run-id>/<scenario-id>/
├── acceptance-result.json
├── screenshot.png
├── requests.json
├── responses.json
├── checks.json
├── model-review.json
└── trace.zip
```

请求记录至少包含 `requestId`、`apiId`、时间、URL、方法、脱敏 query、脱敏 headers 摘要和 body；响应记录至少包含 `requestId`、状态码、耗时、脱敏 headers 摘要和 body。JSON 是默认格式；无法解析的响应保留 `rawBody` 和 `contentType`。

## 5. 模型调用边界

规则引擎直接判定：

- 元素是否存在、可见、可操作；
- 输入值是否改变；
- 请求 URL、方法、query、body；
- 响应状态码和 schema；
- 成功、失败、加载提示；
- 布局溢出、遮挡和视口问题；
- axe 严重问题和控制台错误。

模型只辅助判断：

- 信息层级是否符合 `purpose`；
- 字段主次是否合理；
- 弹窗或抽屉内容是否足以完成任务；
- 文案是否与动作和结果一致；
- 截图中的语义视觉问题。

模型输出必须包含 `finding`、`severity`、`confidence` 和 `evidenceRefs`。模型不能覆盖确定性规则失败，也不能把缺失证据判为通过。

## 6. 标准输出

每个场景输出一个结果对象，整个运行输出一个汇总对象。状态和结论分离：

- `status`：`passed`、`failed`、`blocked`、`reused`、`skipped`；
- `decision`：`pass`、`fail`、`needs_review`。

`reused` 必须保留原结果的 `reusedFrom` 和证据路径。后续 Agent 只需读取 `decision`、`findings`、`checks`、`requests`、`responses` 和 `evidence` 即可继续修复或确认。
